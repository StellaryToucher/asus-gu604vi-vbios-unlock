# 通过交叉刷写 vBIOS 抬高华硕 ROG 幻16（GU604VI）整机功耗预算

**一次可复现的实践记录 —— 整机功耗预算 155W → 175W，CPU 多出约 20W，1% low 显著改善，平均帧基本不变。**

[English version: README.md](./README.md)

---

## 摘要 / TL;DR

把 ASUS ROG 魔霸新锐（Strix G16, 2023, G614JI）的 RTX 4070 Laptop vBIOS 刷入幻16（GU604VI）后，
实测**整机功耗预算从约 155W 抬升到约 175W**。

- **整机总功耗：** 约 155W → **约 175W**
- **CPU 封装功耗（游戏内）：** 约 40W → **约 55–60W**
- **GPU 功耗（游戏内）：** 约 110W → 约 110–120W（未变，受电压/频率限制，并非功耗受限）
- **平均帧：** 基本不变
- **1% low：** **明显变稳**（CPU 瓶颈瞬间的卡顿减少）

也就是说，这次改动**没有抬高性能上限，而是抬高了性能下限**。

---

## 背景

华硕 ROG 幻16（2023，GU604VI）为 i9-13900H + RTX 4070 Laptop GPU（Device ID `10DE-2860`），配 240W 适配器。
在 CPU+GPU 持续负载下，整机会稳定在约 **155W 合计**：GPU 约 110W，CPU 被压到约 40W ——
尽管 CPU 的软件功耗上限（PL1）设置得远高于此，GPU 也从未触及它自己的 140W TGP。

这是典型的**耦合式功耗仲裁**：由 EC（嵌入式控制器）统一执行整机预算，而非让 CPU、GPU 各自为政。

## 假设

许多游戏本的 GPU vBIOS 并不只装显卡参数，还携带了 **EC 用来计算整机功耗预算的平台配置**。
因此，把一个来自**更高功耗平台**（HX 级 CPU + 280W 适配器）的 vBIOS 刷入后，
EC 应当会把整机预算一并抬高；多出来的额度会流向**仍然在索要更多功耗的那一侧**。

本机 GPU 工作在电压/频率甜点（约 110W），**并非功耗受限**，因此它不会去争这部分额度，CPU 会。
预期结果是：CPU 余量增加、帧生成更稳定，而平均帧不变。

## 硬件

| | 目标机 | 供体机 |
|---|---|---|
| 型号 | ASUS ROG 幻16（GU604VI），2023 | ASUS ROG 魔霸新锐 / Strix G16（G614JI），2023 |
| CPU | Intel Core i9-13900H（H 系列） | Intel Core i7-13650HX / i9-13980HX（HX 系列） |
| GPU | RTX 4070 Laptop，Device ID `10DE-2860`，Subsystem `1043-1473` | RTX 4070 Laptop |
| GPU TGP | 140W（115W + 25W Dynamic Boost） | 140W（115W + 25W Dynamic Boost） |
| 适配器 | 240W | 280W |

供体 vBIOS 元数据：

- 文件：`vbios/274670_Asus_ROG_Strix_G614_95.06.15.00.F2.rom`
- VBIOS 版本：`95.06.15.00.F2`
- Subsystem ID：`1043-14D3`；板号：`E3757 SKU 10`；ASID：`N151G614JI.001`
- 出处：TechPowerUp VGA BIOS Collection，条目 `274670`

供体平台（第三方实测，双烤 30 分钟）：

- GPU 约 129W + CPU 约 56W ≈ **185W**（增强模式）
- GPU 约 117W + CPU 约 78W ≈ **195W**（手动模式，风扇全速）

值得注意的是：供体双烤时 CPU 约 56W，与本机刷后实测的 55–60W 高度吻合，
这强烈说明 **EC 采纳了供体的平台行为**。

## 刷写步骤

1. 用 GPU-Z 备份原厂 vBIOS（两份独立副本）。
2. 确认显存厂商（Samsung / Hynix / Micron）与供体 ROM 支持列表匹配。
3. UEFI 中关闭 Secure Boot。
4. 管理员终端执行：

   ```text
   nvflash64 --protectoff
   nvflash64 -6 "vbios\274670_Asus_ROG_Strix_G614_95.06.15.00.F2.rom"
   ```

5. 重启（vBIOS 改动仅在下次开机时生效）。
6. 用 GPU-Z 与 HWiNFO 核对。

## 实测结果

| 项目 | 原厂 vBIOS | 供体（G614JI）vBIOS |
|---|---|---|
| VBIOS 版本 | 原厂 | `95.06.15.00.f2` |
| Default Power Limit | 80W | **100W** |
| Max Power Limit | 140W | 140W |
| 整机功耗预算（实测峰值） | 约 155W | **约 175W** |
| CPU 封装功耗（游戏内） | 约 40W | **约 55–60W** |
| GPU 功耗（游戏内） | 约 110W | 约 110–120W |
| 平均帧 | 基准 | 不变 |
| 1% low | 基准 | **明显改善** |

整机预算未达到供体的 185–195W，说明目标机自身的 EC 与 240W 适配器在约 175W 处又加了一道上限。

## 原理

1. GPU vBIOS 不只携带显卡的 TGP / Dynamic Boost，还携带 EC 用来仲裁整机预算的**平台功耗配置**。
2. 供体是**更高功耗的 HX 平台**；EC 读到新值后，把整机预算从约 155W 抬到约 175W。
3. 本机 GPU 受**电压/频率**限制（约 120W），并非功耗受限，因此没有吸收这部分余量。
4. 余量于是流向 CPU —— 唯一仍在索要功耗的一侧 —— 从而减少 CPU 瓶颈卡顿、改善 1% low。

一句话：**软件设功耗上限是“请求”，vBIOS 改的是 EC 用来计算“允许值”的输入。**

## 注意与风险

- **供电（VRM）是主板硬件**，刷 vBIOS 不会改变。同一 GPU 档位各厂 VRM 相近（本文观察到的
  4070 Laptop ROM 均带同一参考板号 `E3757`）。真正要核的只是“请求功耗是否超出主板设计”——
  140W 在目标机的官方设计范围内。
- **交叉刷写真正的风险不在 VRM**，而在于：EC/子系统 ID 不匹配（动态增强与功耗仲裁）、
  显示接口映射（外接 HDMI/DP）、风扇表、MUX/Optimus 行为。刷后请立刻逐项验证。
- **散热。** 目标机为轻薄模具、CPU/GPU 共用散热模块；预算抬高后发热明显增加，
  CPU 的热量会传导到 GPU，导致 GPU 轻微掉频。本次评估中，**1% low 的收益大于 GPU 掉频的损失**。
  CPU 功耗可用 PL 裁剪（建议 SPL 与 sPPT 一起限，避免短时尖峰）。
- 在 175W 预算、GPU 约 120W 的前提下，CPU 的实际天花板约为 55W（175 − 120）。

## 可复现性

本记录为**单机案例**，非受控基准测试。结果取决于具体 EC 固件、适配器与芯片体质。
请自行承担风险复现，并始终保留原厂 ROM 备份与 U 盘恢复环境（PE + nvflash）以便盲刷回滚。
